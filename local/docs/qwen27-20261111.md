# Dense Qwen3.8 27B: standard decoding and MTP

Measured on November 11, 2026. The two-token MTP option improved decode speed
from 2.99 to 5.37 tokens/s. Both options passed the OMP repair, recall, required
tool, and strict resume checks. Keep Flash-Next as the preferred Qwen option
on this machine. Its earlier measurements were much faster.

The dense model is available as `localmodel start qwen3.8-27b`. Use
`localmodel start qwen3.8-27b mtp` for the measured MTP configuration. The
download is complete and its SHA256 check passed. Existing model defaults
remain unchanged.

## Settings and method

The host uses an RTX 4070 SUPER with 12 GiB VRAM under WSL. Both runs used the
same `Qwen3.8-27B-UD-Q4_K_M.gguf`, pinned to Unsloth revision
`ce331efc48d5722b4b8041f72793e530eae18d9b`. The file is 16,564,259,744 bytes
(15.43 GiB) and contains the MTP head. Its SHA256 is
`1bce504dfecd84153666928a41d8a66706f0158d3a317bc5196b72819d7dc529`.

The runtime is llama.cpp b11946, commit
`8ca4060b7e30e76baaa5670ee1ec1b760b7f8552`. Both runs used 196,608-token
capacity, Q4 KV, automatic GPU layer fitting, flash attention, one slot,
2048/256 batch/microbatch sizes, an 8 GiB prompt snapshot budget, and a
48 GiB cgroup cap with zero swap. The guard was configured to stop below
8 GiB available Linux RAM. Windows memory was not monitored.

The existing OMP fixture supplies a constructed public-source history. OMP
must read and repair `clamp`, run 100 assertions, recall three facts from the
history, and answer a strict JSON probe after resume. Each arm starts a fresh
server and private OMP state. Both initial requests contain 15,997 tokens.
This tests a filled 16K workload, not a filled 192K conversation.

OMP uses xhigh reasoning, temperature 1, top-p 0.95, replacement edits, and a
4096-token response limit. The server uses top-k 20, min-p 0, and repetition
penalty 1. No seed is fixed. Each arm uses five model requests. Throughput
below is total generated tokens divided by total native decode time. It
includes reasoning and tool-call tokens. Prompt sizing does not run inference.

## Results

| Measurement | Standard | MTP, two draft tokens |
| --- | ---: | ---: |
| Initial uncached input | 15,997 tokens | 15,997 tokens |
| Initial prefill | 383.90 tokens/s | 310.31 tokens/s |
| Initial time to first token | 41.71 s | 51.58 s |
| Aggregate decode | 2.99 tokens/s | 5.37 tokens/s |
| Generated tokens | 842 | 698 |
| Native decode time | 282.02 s | 130.06 s |
| Repair wall time | 320.06 s | 190.03 s |
| Resume wall time | 20.00 s | 20.00 s |
| Combined OMP wall time | 340.07 s | 210.04 s |
| Largest actual input | 17,113 tokens | 16,972 tokens |
| Accepted/generated draft tokens | Not applicable | 431/528, 81.63% |
| Peak charged server RAM | 24.19 GiB | 14.73 GiB |
| Peak whole-GPU VRAM | 11,741 MiB | 11,517 MiB |
| Minimum available Linux RAM | 83.92 GiB | 81.40 GiB |
| Model swap / OOM kills | 0 / 0 | 0 / 0 |
| Repair, recall, tools, strict resume | Pass | Pass |

MTP improved aggregate decode by about 80%. Initial prefill fell by about 19%.
The combined task finished about 38% sooner, but it also generated about 17%
fewer tokens. This is one sampled trajectory per arm, not a fixed-output
speedup or a general capability evaluation. Later requests reuse cached
prefixes; their prefill rates do not measure cold processing of the full input.

Native per-request rates exclude the first generated token from the decode
numerator. Aggregating with that convention gives 2.97 and 5.33 tokens/s.
The main table uses the total-output convention used by our other reports.

Automatic fitting may change GPU placement when MTP needs additional memory.
These are comparisons of the usable configurations. They do not isolate the
draft algorithm from placement. Charged RAM includes file cache, and the MTP
run followed the standard run. The lower MTP charge does not establish that
MTP saves RAM. Process and cgroup disk counters were unavailable; no measured
SSD throughput is reported. The MTP `/props` response reported a default
`speculative.types` value of `none`; native draft counters and per-request
acceptance logs confirm that MTP executed.

Our earlier Flash-Next UD-IQ1_M run on Strata 0.2.12 measured 53.38 decode
tokens/s at its 16K checkpoint and 52.17 across 16K through 180K checkpoints.
Its initial prefill was 1329.9 tokens/s. Those runs used a different runtime,
quantization, and memory layout. They are historical context, not a new
controlled model comparison. See the [Flash-Next measurements](strata-0.2.12-measurements.md).
The dense model's smaller file does not imply faster decoding: its dense
layers execute for every token, including layers placed on the CPU.

## Failures, corrections, and cleanup

Two attempts stopped before inference because optional I/O counters were
missing in this WSL environment. The guard and workload now permit missing
I/O counters. Required memory counters remain guarded. A later admission
check refused a port still in TCP cleanup; it succeeded after the port was
released. No user service was stopped.

The standard workload completed successfully, but its cleanup wrapper returned
an error after its worker had already exited. Cleanup now accepts that race.
Its summary also incorrectly recorded seed 424242. The runtime does not bind
`LLAMA_ARG_SEED`, and every request omitted `seed`. The summary contains an
explicit metadata correction. These fixes did not change the inference
requests between arms.

Both server controllers and scopes stopped. Ports 8899 and 8888 closed.
The active model state was removed. The temporary search service stopped.
The GPU had no compute processes after cleanup. Normal OMP settings were not
changed. Raw evidence remains local under the ignored
[`results/qwen27-20261111`](../results/qwen27-20261111/) directory. It includes
failed attempts, native timings, resource samples, request records, source
hashes, and [`comparison.json`](../results/qwen27-20261111/comparison.json).
The reproducible procedure is in
[`experiments/qwen27-20261111`](../experiments/qwen27-20261111/README.md).
