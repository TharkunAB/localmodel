# Edge0 145B on the 12 GiB GPU, November 13

Edge0 145B ran with Q3_K experts and Q4 D/U projections, but these configurations
did not complete the OMP repair task. The plain run repaired the requested
function before its request budget expired. It also changed two functions
outside the requested scope. Keep Qwen Flash-Next as the normal OMP choice.
No Edge0 production default was added.

This result applies to the tested Q4 D/U configuration. Edge0 145B's published
default uses Q8 D/U, which we did not test. It does not establish the quality
of Edge0 generally or reproduce the vendor's benchmarks.

## Pins and conditions

The source is [Edge0-AI/Edge0 at
`da9cc526747759227714ddde0728763d95306c04`](https://github.com/Edge0-AI/Edge0/tree/da9cc526747759227714ddde0728763d95306c04).
The weights are [Edge0/Edge0-145B-q3k at
`00f91ca2dc8290d74c79360f0d9941704e0f5c69`](https://huggingface.co/Edge0/Edge0-145B-q3k/tree/00f91ca2dc8290d74c79360f0d9941704e0f5c69).
The [manifest](../experiments/edge0-20261113/manifest.json) pins 74 files,
105,367,217,462 bytes, or 98.13 GiB. This includes both D/U formats.
The [bounded audit](../experiments/edge0-20261113/audit.md) covers the selected
build and serving path. The launch command uses the existing outgoing-network
guard. Downloaded startup scripts and model configuration commands are not run.

Edge0 uses its own Strata fork, whose native engine reports **0.1.55**.
The official Qwen runtime remains Strata 0.2.13/native 0.1.59. The Edge0 build
and kernel-library hashes are recorded in each case's `build-receipt.json`.
The [experiment guide](../experiments/edge0-20261113/README.md) documents the
isolated build and runner.

All three runs used **32,768-token capacity and 15,992 initial input tokens**,
a 64 GiB model cgroup, zero swap, a 40 GiB expert budget, INT8 KV, direct FP8
embedding-table reads, and Q4 D/U projections. The token embedding stayed in
RAM and the U projection stayed on the GPU. OMP and its tools had a separate
4 GiB cap. The history came from the public-source fixture, with the seed
20261113 and `xhigh` reasoning. The Linux available-memory stop floor was 8 GiB.

The initial MTP run used three drafts, a 300 MiB GPU reserve and 32,768 GPU KV
cells. It inherited the fork's expert tail-skip value of seven. The later plain
and small-vocabulary MTP runs explicitly disabled tail skipping and suffix
drafting. Plain mode omitted the MTP layer, used an 800 MiB reserve and retained
32,768 GPU KV cells. Its native `--spec 2` is the minimum supported window;
the zero draft counters confirm that it did not speculate. Small-vocabulary
MTP used three drafts, the 40,525-token English draft vocabulary, a 550 MiB
reserve and 20,480 GPU KV cells.

## Measurements and task results

Decode rates divide generated target tokens by the sum of native decode time.
They exclude prefill, tools and startup. Initial prefill rates use the first
15,992-token request with no reused context. RAM is the model cgroup peak.
GPU memory is the highest sampled device usage, including other GPU allocations.

| Run | Decode tokens / seconds | Decode tok/s | Initial prefill tok/s | MTP accepted / offered | Peak RAM GiB | Peak GPU MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Initial MTP | 1,684 / 45.2059 | 37.25 | 283.97 | 1,130 / 1,317 | 44.38 | 11,705 |
| Plain, stopped at request limit | 7,170 / 335.9168 | 21.34 | 686.24 | 0 / 0 | 45.19 | 11,365 |
| Small-vocabulary MTP | 96 / 4.1494 | 23.14 | 300.05 | 35 / 49 | 44.68 | 11,387 |

Initial MTP made no tool calls and failed the code and recall checks. The
repair and resume phases took 110.49 seconds. Startup reported only 57 MiB
free VRAM, followed by a zero-free-VRAM warning on the first request. Tail
skipping was active, so this result must not be used as a clean MTP speedup.

Plain mode reached the 16-request budget after 381.67 seconds, with 16 tool
calls and eight tool errors: five from `bash` and three from `read`. The
benchmark stopped before a final answer or resume probe. Independent
`posthoc-validation.json` records that the unchanged validator's 100 target
assertions passed. The saved code also changed `clamp_index` and `clamp_many`
in addition to the requested `clamp`. The overall task therefore remained
incomplete and violated its edit scope.

Small-vocabulary MTP made no tool calls and failed code and recall. Its repair
response contained only eight generated tokens; the resume probe added 88.
The **96-token decode sample is too small for a stable throughput estimate**.
The repair and resume phases took 70.25 seconds. The resume probe passed,
but that does not establish repair success. Startup had 540 MiB free VRAM;
a later request still produced a low-headroom warning at 367 MiB.

For comparison, the first 16K checkpoint in Qwen's `q8192-matched64-r1` and
`q8256-matched64-r1` runs decoded at **49.84 and 52.66 tok/s**, with initial
prefill at **1,345.59 and 1,577.18 tok/s**. Both passed semantic code and recall
checks. Their initial inputs were 15,997 tokens under Qwen's template. The
[Qwen report](qwen-engram-20261113.md) retains the strict JSON-format caveat.
These comparisons use the same task fixture but different models, templates,
engines, capacities and outputs. The Edge0 runs also changed several settings.
They do not isolate the effect of MTP, D/U precision or expert tail skipping.
We did not run Edge0 at 192K or 256K after these short-task failures.

## Evidence and cleanup

Local evidence is under `local/results/edge0-20261113/`:

- `q3k-q4-32768-short-20261113`: initial MTP.
- `q3k-q4-plain-32768-short-20261113`: incomplete plain run and independent validation.
- `q3k-q4-mtp-small-32768-short-20261113`: small-vocabulary MTP.

Each directory retains native logs, measurements, captured requests, build and
artifact receipts, and cleanup records. The failed attempts are retained too:
`failed-metrics-import` failed before launch; `failed-32k-vram-embedding-reserve1024`
had no room for the required GPU expert cache; `failed-plain-native-window1`
was rejected because a native pack requires a window of at least two.

The three measured runs recorded no cgroup OOM events and zero swap use.
Their owned servers, workers and guards stopped. Port 8899 closed, owned
active records were removed, and normal OMP settings were unchanged. The
preexisting search service was preserved. Removing the Edge0 weights does
not remove these results, pins, audit or preparation scripts.
