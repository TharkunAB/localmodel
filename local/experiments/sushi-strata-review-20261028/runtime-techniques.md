# Sushi runtime techniques and Strata

Reviewed 2026-10-28. This report describes source inspection and published measurements. It does not report a local inference benchmark. It does not change an engine or a tuning option.

## Current configuration and candidate work

| Mechanism | Current local behavior | Sushi behavior | Assessment |
| --- | --- | --- | --- |
| Expert memory | Qwen uses 32 GiB resident RAM and an automatic VRAM cache. DeepSeek uses a 36 GiB launcher budget for its RAM store. | A unified-memory expert budget includes resident trunk and draft weights. Layer allocation can use hits per byte. | Measure cache misses and memory pressure first. A Mac budget is not equivalent to a discrete GPU budget. |
| DeepSeek prefill | Explicit 4096-token chunks. Full six-expert routing. | Memory admission selects a chunk size and can borrow decoder expert pools. | Compare 4096 with 8192 on this host. Do not import a Mac chunk size as a default. |
| Qwen speculation | MTP with three drafts, a four-row verify window, and confidence floor 0.5. Prompt lookup is disabled. | MTP is the default. DFlash2 is optional. The verifier has specialized row-width kernels. | Measure accepted tokens per millisecond before increasing the window. |
| Qwen state recovery | Strata already replays accepted GDN rows and batches state commits. | Sushi replaced full per-row GDN snapshots with accepted-prefix replay. | The main technique already exists. A second implementation is not justified. |
| Cost-aware draft depth | Strata contains an experimental `STRATA_SPEC_COST` policy. The launcher does not enable it. | Sushi measures round costs and limits low-yield speculation. | Candidate for a separate experiment. Keep it off in the current profile. |

| DeepSeek DSpark | Disabled by the reviewed local profile. | Enabled by default when the pack contains its draft stages. | Its resident memory and extra expert reads can outweigh accepted drafts. Keep the current setting. |

## Expert memory and I/O

A small expert cache and a wide speculative window can multiply expert I/O. More proposed tokens can select more distinct experts. Rejected drafts still consume reads and compute. Draft weights also reduce the space available to target-model experts. The relevant metric is committed tokens per total round time.

Strata's DeepSeek auto-policy records this constraint explicitly. Where routed experts exceed GPU capacity by more than 1.5 times, a verify round can read about 3.3 times a plain token's expert bytes. The drafter can also displace approximately 7 GB of hot experts. These are upstream observations, not measurements of our profile. [Strata DSpark policy](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_model.hpp)

Sushi uses per-layer LRU caches. An optional profile allocates bytes by decode hits per byte. Its expert-usage warmup improved one 600-token run from 43.4 to 46.5 tokens/s. A second run without misses remained at 50.2 tokens/s. This supports a cold-cache benefit only. Strata already loads an expert profile, updates expert residency, and settles the VRAM cache after a prompt. Qwen can also save a learned profile between starts. Measure these existing mechanisms before adding another cache policy. [Sushi cache policy](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/engine-expert-streaming.md#cache-policy), [Strata cache settling](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_model.cu), [Qwen profile persistence](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/program/generate.cpp)

Strata already evaluated predicted expert reads with its RAM store. At 62% prediction accuracy, measured decode fell from 4.7 to 4.5 tokens/s because incorrect predictions consumed SSD bandwidth. The store therefore disables lookahead unless explicitly requested. The `ahead_layer` selector also requires MXFP4, so this path does not directly support our IQ1_M file. Sushi's three-layer lookahead runs only for two or more verify rows. At one row, its prediction and synchronization cost exceeded the saved misses. [Strata `init_store` and `ahead_layer`](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_model.cu), [Sushi decode schedule](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/engine-expert-streaming.md#decode-schedule)

Both runtimes already overlap Engram reads. Strata requests rows when token IDs are known, reads layer 1 before it is needed, and reads layer 14 while earlier layers run. Its bounded cache reuses repeated rows. Prompt processing has two Engram buffers in flight. Sushi reports a prose prefill gain from next-chunk reads, but this does not establish a missing Strata mechanism. [Strata Engram reader](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_engram_io.hpp), [Strata `layer_chunk`](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_model.cu), [Sushi DeepSeek architecture](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/dsv41-arch.md)

## Speculative decoding

Sushi reduced its Qwen eight-row verify time from about 44.5 to 37.4 ms on an M5 Max. It extended prepared verifier graphs, selected dense kernels by row width, and replayed accepted GDN rows instead of saving every intermediate state. Strata already implements the replay and batches its state commit. This does not prove that all row widths perform well on our GPU. A row-width timing curve is required before a kernel change. [Sushi Qwen performance details](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/qwen4-perf.md), [Strata verifier](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/core/verify.cpp)

The Strata `STRATA_SPEC_COST` experiment estimates committed tokens per millisecond. It learns acceptance by draft probability and costs by context range. It reduces the influence of first-use graph capture and slow outlier rounds. It is disabled in the local profile. Sushi itself reverted an acceptance-based depth policy when longer rounds reduced throughput. High acceptance alone is insufficient. [Strata draft policy](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/include/strata/spec/draft_policy.hpp), [implementation](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/spec/draft_policy.cpp), [Sushi reverted policy](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/qwen4-perf.md#mtp-depth-policy-one-chunk-from-acceptance-emas-below-8k-kv-reverted)

DFlash2 is not a server replacement in the inspected Strata code. Its load guard rejects `--serve`, `--batch`, and a layer split. It requires MTP as fallback and approximately 1.2 GiB extra VRAM. The upstream 12 GB NVIDIA comparison favored MTP in most cases. A six-token window gained 3% on code. This is a low-priority experiment for this GPU. [Strata DFlash2 load guard and measurements](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/program/generate.cpp#L6220)

## Prefix reuse

Sushi stores DeepSeek compressed rows in append-only 8192-token segments. It stores window rings and open pooling groups in separate small checkpoints. Its live state retains eight recent rollback points. A later request can reuse the deepest valid point without reading the SSD. Strata already has live rollback, but it retains four checkpoints with fixed roles. Its optional disk slots serialize conversations. The local launcher explicitly disables those slots. [Sushi prefix cache](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/dsv41-arch.md#prefix-cache), [Strata state checkpoints](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_model.cu), [Strata conversation reuse](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/src/dsv41/ds4_main.cpp)

The useful new idea is a checkpoint immediately after `</think>` in a tool-using turn. The next prompt can preserve the reasoning tokens but render a tool-call argument differently. An end-of-answer checkpoint then occurs after the first mismatch and cannot be reused. Sushi's reasoning checkpoint can preserve 5,000 to 20,000 tokens in this case. Its implementation requires verbatim returned reasoning, excludes some whitespace cases, and currently applies to DSpark with the SSD tier. A Strata implementation must handle the serial decoder's token/state position explicitly. It cannot copy the condition unchanged. [Sushi reasoning checkpoint and token-template cases](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/dsv41-arch.md#prefix-cache)

Qwen already uses bounded checkpoints. Its default is six checkpoints and a 16,384-token periodic cadence. Optional near-tail and message-boundary checkpoints address edited prompts. The near-tail option does not split a prefill chunk. The message-boundary option can split one. Both have limits and incomplete validation claims in their documentation. They are research candidates, not settings to enable during this update. [Tail checkpoint](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/docs/PROMPT_CACHE_TAIL.md), [message-boundary checkpoint](https://github.com/Niko1221/Strata/blob/5e8a4cca7d690ac60ca37eb09e7d0e010099ad6d/docs/MESSAGE_BOUNDARY_CACHE.md)

## Minimal experiment order and gates

1. **Record the current baseline.** Use one model at a time. Keep the 64 GiB process cap, current expert budgets, current quantization, full DeepSeek routing, and current speculation. Record the binary hash, effective cgroup limits, context, peak memory, prompt reuse, expert-cache hits, SSD bytes, and draft acceptance. Include code, prose, and tool calls. Separate cold and warm requests.
2. **DeepSeek prompt chunks: 4096 versus 8192.** Use identical prompts at 4K, 8K, and 32K. Keep all other settings fixed. Record full request time and subsequent decode as well as prefill. Pass only if memory fits and the paired quality checks show no material regression. Different chunk geometry can change floating-point results, so greedy byte equality is evidence but not the sole quality gate.
3. **Expert RAM allocation.** Keep the existing 32/36 GiB values as controls. Only select one larger candidate after measuring the complete process and cgroup usage. It must fit inside 64 GiB with explicit room for context, pinned buffers, page cache, and transient allocations. Compare SSD reads and useful task time. A larger process cap alone does not establish a larger safe expert budget.
4. **Measure reuse before implementing checkpoints.** Record shared-prefix length and reused tokens on ordinary continuations and tool turns. Include arrays, escaped strings, trimmed reasoning whitespace, an edited earlier message, and a side conversation. If repeated reasoning is reread, prototype one bounded reasoning-boundary checkpoint in an isolated source build. Preserve image identity, token identity, model identity, and cancellation ordering. Compare restored state with a cold run using matching chunk boundaries.
5. **Qwen verifier widths.** Keep MTP and compare the current three drafts with one smaller and one larger window. Record draft, verify, commit, cache-miss, and accepted-token costs. Use the same code and prose tasks. Test all partial-accept positions and the next round. Only then evaluate the existing cost-aware policy in a separate experimental profile.
6. **Larger changes only after attribution.** DSpark, DFlash2 server integration, predicted expert reads for IQ1_M, and new CUDA kernels require separate evidence. A change must remove a measured cost on this host. It must not substitute lossy expert selection for an exact scheduling change.

For exact scheduling changes, compare the same state and logits through serial and changed schedules. Include real weight scales and cancellation. For different quantizations, compare logits with the same original checkpoint, tokenizer, input IDs, and fixture. Add end-to-end tool and code checks. KLD from different fixtures is not a ranking. Timing comparisons should alternate control and candidate order. Measure multiple runs after warmup. Do not infer a speedup from different generated lengths or a changed acceptance rate alone.

Keep the deliberately disabled settings disabled: `STRATA_DS4_DISK_SKIP_W=0`, `STRATA_DS4_SLOT_KEEP=0`, `STRATA_ROUTE_PRIOR=0`, prompt lookup off, and DeepSeek speculation off. In particular, disk-based expert skipping changes the model output and depends on residency. It is not equivalent to prefetching.

## Published benchmark limits

Sushi v1.4.0 was measured on an Apple M5 Max with 128 GB unified memory. Runs used AC power, maximum fans, controlled initial temperature, one model per server, and default speculative decoding. Each context level has three greedy decode samples. Qwen samples contain 512 generated tokens. DeepSeek samples contain 256 code tokens or 128 prose tokens. Prefill grows one prompt through restored windows; a 128K row is not a fresh 128K cold prefill. The report says its new `sushi bench` figures are not comparable with earlier llmprobe reports. [Pinned benchmark protocol](https://github.com/beamivalice/sushi/blob/956fe27f4e19ccefbd4f6bddf7c32eb67d8cc71c/docs/bench/v1.4.0/summary.md)

| Pack | 4K code decode | 4K prose decode | 128K code decode | 128K prose decode |
| --- | ---: | ---: | ---: | ---: |
| Qwen STQ 2.75bpw | 168.6 | 62.8 | 138.2 | 71.5 |
| DeepSeek STQ 1.75bpw, 108 GiB budget | 76.6 | 49.3 | 63.7 | 43.5 |

All values are published tokens/s. They are not predictions for our hardware. The code/prose difference shows how much speculative acceptance changes throughput. The DeepSeek benchmark also has far more resident expert memory than our profile. Our benchmark must separate quantization quality, expert I/O, and speculative decoding before attributing a gain to STQ.
